# دفتر ضدبازپخش گواهی بازبینی انسانی

این ماژول یک نمونه آزمایشی تک‌میزبان برای مصرف یک‌باره گواهی Ed25519 بازبینی است. به سرور HTTP دادیار متصل نیست و مجوز انتشار یا احراز هویت واقعی ایجاد نمی‌کند.

## رفتار

- ابتدا امضای گواهی، نقش بازبین، زمان اعتبار و اتصال آن به commit، Git blob فایل پیش‌نمایش و SHA-256 بسته را با verifier موجود بررسی می‌کند.
- سپس دو شناسه مستقل را به‌صورت SHA-256 ذخیره می‌کند: شناسه بازبینی و nonce.
- فایل‌های نشانگر با ایجاد انحصاری فایل (O_EXCL) ساخته می‌شوند؛ فقط یک فرایند می‌تواند همان شناسه یا nonce را مصرف کند.
- فقط digestها، commit، digest بسته و زمان مصرف ذخیره می‌شوند. نام بازبین، شناسه خام بازبینی و nonce خام ذخیره نمی‌شوند.
- اگر ایجاد یکی از دو نشانگر انجام شود و عملیات بعدی شکست بخورد، نشانگر قبلی پاک نمی‌شود. این رفتار عمداً fail-closed است؛ ممکن است گواهی بدون دریافت گزارش مصرف شود و برای تلاش مجدد باید بازبینی تازه صادر شود.

## پیش‌نیاز محل ذخیره

پوشه دفتر باید پیشاپیش توسط اپراتور ایجاد شود، مالک آن همان کاربر سیستم‌عامل اجرای فرایند باشد، مجوز آن فقط برای مالک (معمولاً 0700) باشد، هیچ مؤلفه مسیر symlink نباشد و مسیر آن کاملاً خارج از checkout مخزن قرار گیرد. ماژول پوشه یا کلید ایجاد نمی‌کند.

نمونه فراخوانی در یک ابزار محلی مورد اعتماد:

~~~js
const { consumeHumanReviewAttestation } =
  require('./backend/human-review-replay-ledger.cjs');

const result = consumeHumanReviewAttestation({
  attestation,
  trustStore,
  expectedSourceCommit,
  expectedSourceBlobSha1,
  expectedArtifactSha256,
  ledgerDirectory: '/absolute/private/path/dadyar-review-ledger'
});

if (!result.consumed) {
  // fail closed: no report delivery
}
~~~

## محدودیت‌های امنیتی

- این پیاده‌سازی فقط برای یک میزبان و فایل‌سیستم محلی با semantics اتمیک O_EXCL است. برای چند میزبان، NFS یا محیط توزیع‌شده از جدول دیتابیس با unique constraint و تراکنش استفاده شود.
- ماژول به backend/server.js یا مسیر HTTP وصل نشده است؛ آزمون موفق آن اثبات احراز هویت یا تحویل گزارش در سایت نیست.
- کلید عمومی در trust store فقط امضای کلید را بررسی می‌کند؛ هویت واقعی بازبین باید از سامانه هویت مستقل و کانال مورد اعتماد مالک احراز شود.
- دفتر باید تا پایان دوره‌ای که گواهی می‌تواند پذیرفته شود نگهداری شود. حذف زودهنگام نشانگرها امکان بازپخش را برمی‌گرداند.
- در صورت توقف فرایند پس از ثبت نشانگر و پیش از پاسخ، گواهی مصرف‌شده تلقی می‌شود. این طراحی at-most-once است، نه تضمین تحویل.
- این ماژول هیچ اتصال شبکه‌ای، API هوش مصنوعی، cPanel، دیتابیس تولید یا استقرار انجام نمی‌دهد.

## آزمون

فایل tests/human-review-attestation-replay.test.cjs نه آزمون ساختگی دارد، از جمله رقابت هشت فرایند مستقل برای مصرف یک گواهی؛ دقیقاً یک فرایند باید موفق شود.
