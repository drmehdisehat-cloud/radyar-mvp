# بسته عمومی پیش‌نمایش دادیار، صرفاً برای بازبینی

این Workflow فقط روی push شاخه آزمایشی `dadyar/ai-chat-private-20261101` اجرا می‌شود. ZIP نهایی Artifact دقیقاً **دو فایل** در ریشه آرشیو دارد:

- `index.html`: نسخه ایستای پیش‌نمایش از `dadyar-preview/index.html`.
- `INTEGRITY.json`: manifest عمومی که SHA-256 فایل HTML، شناسه commit مبدأ و مسیر هدف را ثبت می‌کند.

## تفکیک بسته داخلی و Artifact عمومی

سازنده ابتدا یک بسته موقت با دو پوشه می‌سازد:

- `public/`: ابتدا فقط `index.html` دارد؛ سپس سازنده manifest، فایل `INTEGRITY.json` را به همین پوشه اضافه می‌کند.
- `handoff/`: شامل `PREVIEW-METADATA.json`، `README-fa.txt` و `SHA256SUMS` برای اپراتور است. این پوشه و محتوای آن در ZIP عمومی بارگذاری نمی‌شوند.

Workflow آرشیو را از داخل پوشه `public/` می‌سازد و پیش از بارگذاری، verifier فهرست دقیق دو فایل `index.html` و `INTEGRITY.json` را کنترل می‌کند. تغییر ناخواسته نام، فایل اضافه یا فایل مفقود باید باعث شکست آزمون شود.

## ماهیت و محدودیت Artifact

- این Artifact فقط برای مشاهده و بازبینی نسخه ایستای سناریوی کاملاً ساختگی چک است.
- مخزن در حال حاضر عمومی است؛ بنابراین باید فرض کرد کد و Artifact برای عموم قابل مشاهده یا دریافت‌اند. هیچ داده موکل، رمز، کلید API، داده واقعی یا سند محرمانه وارد نکنید.
- پیش‌نمایش آفلاین است و از API یا شبکه خارجی استفاده نمی‌کند؛ API و گفت‌وگوی هوشمند عمومی خاموش‌اند.
- ثبت بازبینی داخل صفحه فقط اظهار محلی است. هویت، سمت و استقلال بازبین احراز نمی‌شود؛ زمان دستگاه نیز مهر زمانی معتبر نیست.
- `INTEGRITY.json` فقط تمامیت فایل و اتصال آن به commit را بررسی‌پذیر می‌کند؛ اثبات Restore، اعتبار مقصد، هویت بازبین، صحت حقوقی یا مجوز انتشار نیست.
- Artifact مجوز استقرار روی `mehdisehat.ir` نیست و جایگزین Restore مستقل، احراز هویت بازبین، بررسی امنیت، اعتبارسنجی مقصد یا مجوز صریح مالک نمی‌شود.
- Artifact فقط هفت روز نگهداری می‌شود و نام آن SHA کامل commit مبدأ را دارد.

## روش بازبینی

1. در GitHub Actions اجرای Workflow با نام **Dadyar public-only preview review artifact** را باز کنید.
2. Artifact متناظر با SHA کامل commit موردنظر را دریافت کنید.
3. ZIP را در محیط محلی ایزوله باز کنید و بررسی کنید فقط دو فایل `index.html` و `INTEGRITY.json` در ریشه آن وجود داشته باشد.
4. مقدار `source_sha256` در `INTEGRITY.json` را با SHA-256 محاسبه‌شده از `index.html` تطبیق دهید؛ `source_commit` باید با commit بازبینی‌شده برابر باشد.
5. فقط محتوای HTML را با داده ساختگی بازبینی کنید. برای این Artifact، احراز هویت واقعی بازبین وجود ندارد.
6. تا وقتی همه دروازه‌های انتشار تأیید نشده‌اند، هیچ فایلی را روی هاست بارگذاری نکنید.

## ممنوعیت انتشار

تا اثبات بازیابی بکاپ در Sandbox جداگانه، اعتبارسنجی مقصد، احراز هویت واقعی بازبین، بازبینی مستقل امنیتی و حقوقی و مجوز صریح مالک، این Artifact صرفاً بسته بازبینی است. هیچ فایل، DNS، دیتابیس یا مسیر تولید با این Workflow تغییر نمی‌کند. هیچ گام CI در این Workflow استقرار انجام نمی‌دهد.
