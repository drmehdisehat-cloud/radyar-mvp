# ترکیب دروازه بازبینی امضاشده

**وضعیت: ترکیب قابل‌آزمایش؛ هنوز به ارائه‌دهنده هویت یا سرور سایت متصل نیست.**

فایل \`backend/signed-review-release-gate.cjs\` سه جزء موجود را در یک تابع دروازه سمت سرور ترکیب می‌کند:

1. احراز هویت بازبین از طریق callback مورد اعتماد سرور؛
2. اعتبارسنجی گواهی Ed25519 متصل به commit، Git blob صفحه پیش‌نمایش و SHA-256 بسته؛
3. مصرف یک‌باره شناسه بازبینی و nonce از دفتر محلی ضدبازپخش.

سپس فقط گزارش بارگذاری‌شده از مخزن سمت سرور را، در صورت تطبیق SHA-256 دقیق، به adapter تحویل می‌دهد.

## قرارداد تزریق وابستگی

- \`authenticateReviewer(request)\` باید نشست را از ارائه‌دهنده هویت واقعی سمت سرور احراز کند و فقط یک principal معتبر شامل \`authenticated\`, \`issuer\`, \`subject\`, \`roles\` و \`independent\` برگرداند. هیچ‌یک از این فیلدها از بدنه درخواست گرفته نمی‌شوند.
- \`trustStore\` باید از کانال مستقل مالک pin شده باشد. ماژول در زمان ساخت، snapshot عمیق و تغییرناپذیر می‌گیرد.
- \`loadReviewedReport(target)\` باید بایت‌های همان گزارش/Artifact بازبینی‌شده را از مخزن سمت سرور بخواند. SHA-256 آن باید دقیقاً با \`artifact_sha256\` گواهی برابر باشد.
- مسیر دفتر ضدبازپخش باید مطلق، canonical، خصوصی، خارج از checkout و متعلق به UID سرویس باشد. ماژول دفتر فعلی فقط برای یک میزبان و فایل‌سیستم محلی طراحی شده است.

## ترتیب عملیات

1. احراز هویت نشست؛
2. الزام نقش بازبین و استقلال او؛
3. تطبیق issuer و subject نشست با گواهی امضاشده؛
4. اعتبارسنجی امضا، زمان اعتبار و شناسه‌های commit/blob/Artifact؛
5. بارگذاری گزارش و بررسی اندازه و SHA-256؛
6. مصرف اتمیک review ID و nonce؛
7. تحویل بایت‌های گزارش.

گزارش پیش از موفقیت تمام مراحل به caller بازگردانده نمی‌شود. خطای موقت مخزن پیش از مصرف nonce رخ می‌دهد تا بازبین مجبور به صدور گواهی تازه برای یک اختلال ذخیره‌سازی نشود.

## مرز ایمنی

این ماژول یک composition seam است، نه IdP. هنوز موارد زیر فراهم نشده‌اند:

- SSO/IdP واقعی و نگاشت هویت بازبین به شخص مجاز؛
- pin کردن trust store و کلیدها توسط مالک از کانال مستقل؛
- مخزن گزارش immutable و مدیریت چرخه عمر آن؛
- TLS، session، CSRF و اتصال به reverse proxy؛
- دفتر ضدبازپخش بادوام مشترک برای چند instance یا چند میزبان؛
- استقرار در \`backend/server.js\` یا هاست.

بنابراین این ماژول عمداً به سرور اصلی متصل نمی‌شود و هیچ API عمومی را فعال نمی‌کند. آزمون‌ها فقط کلیدها، گزارش، شناسه‌ها و نشست ساختگی را به‌کار می‌برند. نتیجه موفق CI مجوز انتشار نیست.
