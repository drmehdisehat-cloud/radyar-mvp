# راهنمای مالک برای اتصال احراز هویت واقعی بازبین دادیار

**وضعیت فعلی: NOT CONFIGURED.** ماژول‌های JWT و گزارش امضاشده فقط با کلیدها، نشست‌ها و هویت‌های ساختگی آزموده شده‌اند. هیچ ارائه‌دهنده هویت واقعی (IdP/SSO)، حساب بازبین، کلید عملیاتی یا مسیر گزارش عمومی به سایت متصل نیست. این سند مجوز انتشار یا فعال‌سازی API نیست.

## اطلاعات و تصمیم‌هایی که مالک باید خارج از مخزن تعیین کند

1. **ارائه‌دهنده هویت و شناسه دقیق آن**
   - نشانی canonical و HTTPS مربوط به `issuer`؛
   - مقدار دقیق `audience` برای سرویس بازبینی؛
   - شناسه پایدار `subject` برای هر بازبین؛
   - روش احراز چندمرحله‌ای و سیاست غیرفعال‌سازی حساب؛
   - فرایند مستقل تأیید اینکه بازبین از تهیه‌کننده Artifact و اپراتور Restore مستقل است.

2. **کلید نشست و چرخش آن**
   - فقط `RS256` با کلید RSA حداقل ۲۰۴۸ بیت؛
   - `kid` یکتا و کلید عمومی SPKI از قبل pin‌شده؛
   - چرخش کلید با دوره هم‌پوشانی کنترل‌شده، ابطال کلید قدیمی و ثبت اثرانگشت SHA-256 از کانال مستقل؛
   - کلید خصوصی فقط در سامانه مدیریت کلید/رازهای IdP نگهداری شود، نه در Git، Artifact یا گفتگو.

3. **ادعای نشست و ابطال فوری**
   - توکن باید `iss`, `sub`, `aud`, `iat`, `exp`, `jti`, `roles` و `reviewer_independent=true` را داشته باشد؛
   - نقش مجاز دقیقاً `preview-reviewer` است؛ نقش یا ادعای اضافه پذیرفته نیست؛
   - callback سمت سرور برای بررسی وضعیت فعال/باطل‌شده نشست (session revocation) در هر درخواست لازم است؛
   - timeout، قطعی یا پاسخ نامعتبر مخزن ابطال باید fail-closed باشد؛
   - عمر کوتاه JWT جایگزین ابطال سمت سرور نیست.

4. **کوکی و مرز مرورگر**
   - نام ثابت: `__Host-dadyar-review-session`؛
   - ویژگی‌های الزامی: `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/` و بدون `Domain`؛
   - TLS معتبر تا reverse proxy مورد اعتماد؛
   - `Origin` و Fetch Metadata دقیقاً با مبدأ پیش‌نمایش تطبیق داده شوند؛
   - هویت، نقش یا استقلال از `X-Authenticated-User`، `X-Reviewer-Role`، بدنه JSON یا هر سرآیند قابل جعل خوانده نشود.

5. **گواهی بازبینی و Trust Store جداگانه**
   - گواهی تصمیم انسانی با Ed25519 و اتصال هم‌زمان به commit، Git blob صفحه و SHA-256 Artifact؛
   - Trust Store باید subject و نقش مجاز را به کلید بازبین متصل کند؛
   - اثرانگشت SHA-256 بایت‌های Trust Store باید توسط مالک از کانال مستقل pin شود؛
   - کلید امضای گواهی بازبینی از کلید امضای JWT و از کلیدهای Restore جدا باشد.

6. **دفتر ضدبازپخش و گزارش**
   - دفتر nonce/review-id روی فایل‌سیستم خصوصی با مجوز محدود یا ذخیره‌ساز تراکنشی بادوام؛
   - اگر بیش از یک instance وجود دارد، دفتر مشترک با عملیات اتمیک لازم است؛ دفتر محلی تک‌میزبان برای چند instance کافی نیست؛
   - گزارش فقط از مخزن سمت سرور و پس از تطبیق digest دقیق بارگذاری شود؛
   - خطای ذخیره‌ساز، replay، digest متفاوت یا تغییر فایل باید دریافت گزارش را متوقف کند.

## آزمون‌های اجباری در Sandbox مستقل

با داده و کلید ساختگی ابتدا آزمون‌ها را اجرا کنید؛ سپس پس از پیکربندی واقعی IdP، همان ماتریس را در Sandbox تکرار کنید:

- نشست معتبر و بازبین مجاز؛
- کوکی مفقود، منقضی، دستکاری‌شده یا دارای امضای نامعتبر؛
- issuer، audience، subject یا kid اشتباه؛
- نقش اضافی، نقش غیرمجاز یا بازبین غیرمستقل؛
- نشست لغوشده، timeout و قطعی سرویس ابطال؛
- جعل سرآیندهای هویت بدون کوکی معتبر؛
- Origin و Fetch Metadata بین‌مبدأیی؛
- گواهی امضاشده توسط شخص دیگر یا متصل به commit/blob/Artifact دیگر؛
- replay هم‌زمان و replay پس از restart؛
- گزارش تغییرکرده، خالی یا بزرگ‌تر از حد؛
- اطمینان از اینکه در تمام حالت‌های رد، مخزن گزارش حتی یک بار خوانده نمی‌شود.

## ترتیب اتصال و مجوز

1. مالک IdP، شناسه‌ها، سیاست استقلال بازبین و اثرانگشت کلید عمومی را از کانال امن و مستقل تأیید کند.
2. اپراتور، adapter سمت سرور را در Sandbox بسازد؛ هیچ secret یا کلید خصوصی وارد مخزن نشود.
3. آزمون‌های integration با IdP واقعی و لاگ‌های redacted اجرا و به SHA دقیق کد متصل شوند.
4. بازبین مستقل، مبدأ، cookie، TLS، Trust Store، ابطال نشست و دفتر ضدبازپخش را بررسی کند.
5. تنها پس از تأیید مکتوب مالک برای همان مقصد و همان commit، درباره فعال‌سازی مسیر گزارش تصمیم گرفته شود.

**ممنوع:** قرار دادن رمز، OTP، session cookie، access token، private key، API key، داده موکل یا لاگ خام هاست در GitHub، Artifact یا گفتگو. اطلاعات محرمانه فقط از طریق Secret Manager/سامانه میزبانی و با دسترسی حداقلی تنظیم شوند.

## وضعیت فعلی انتشار

تا زمانی که IdP واقعی، نگاشت هویت بازبین، pin مستقل Trust Store، TLS/CSRF، ابطال نشست، دفتر بادوام و آزمون واقعی Sandbox تأیید نشده‌اند:

- `backend/server.js` نباید مسیر عمومی گزارش بازبینی را ثبت کند؛
- پیش‌نمایش صرفاً آفلاین و برای بازبینی است؛
- API و گفت‌وگوی هوشمند عمومی خاموش می‌مانند؛
- آزمون ساختگی یا امضای معتبر با کلید آزمایشی، هویت واقعی یا مجوز انتشار محسوب نمی‌شود.
